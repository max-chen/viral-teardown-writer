# 喂料充分性判定表与五序分支真值表

本文件两张表由 `../scripts/normalize_feed.py` 完整实现，零模型参与，同一喂料两次运行结果逐字节一致。
**充分性判定不得由模型凭感觉决定**——「这坨文字看起来够不够」正是要消灭的东西。

## 喂料级状态

| 状态 | 条件 | 语义 |
|---|---|---|
| `F0` 无有效喂料 | `items` 为空，或全部条目未通过入场券（`n_存活 == 0`） | 等价于「用户未喂料」 |
| `F1` 充分 | `n_可判定 >= 1` | 至少有一条能凭页面可见证据独立判定爆款 |
| `F2` 不足 | `n_存活 >= 1` 且 `n_可判定 == 0` | 有内容但零证据（既无榜标记榜位，也无任何可见互动数字） |

注意这里的 `F0 / F1 / F2` 是**喂料级状态**，与 `feed-schema.md` 里的字段级编号
`F1` 至 `F14` 不同层。读文档时不要混。

「喂了但全部条目缺标题或缺地址」归 **F0** 而不是 F2：`n_存活 == 0` 时没有任何条目
进入判定，语义上就是「没喂到可用内容」；归 F2 会把「缺入场券」误报成「缺数字」，
误导用户的喂料方向。

## 基线是否参与充分性

`baselines` 缺失**不**参与充分性判定（常量 `baseline_required_for_sufficiency`，
默认 `false`）。

理由：条件①（榜单）独立成立。若把「缺基线」算作不足，「喂了完整榜单列表」这个最典型的
喂料场景会被迫联网，直接违反序 1「不上网」。

裁决若翻转为 `true`，只需改这一个常量（或传 `--baseline-required`），真值表分支不变。

## 五序分支真值表

输入只有两个：`feed_state` 与 `d2_available`。**按序短路**，编号与需求书一一对应。

| feed_state | d2_available | branch | d2_allowed | d2_scope | 输出 |
|---|---|---|---|---|---|
| F1 充分 | 任意 | **序 1** | `false` | 无 | 用喂料出结果（至少 1 条） |
| F2 不足 | `true` | **序 2** | `true` | `fill_evidence_gap`（仅补证据缺口） | 喂料条目与读到的条目**合并进同一排序** |
| F2 不足 | `false` | **序 3** | `false` | 无 | **0 条** + blockers |
| F0 无效喂料 | `true` | **序 4** | `true` | `full_search`（自主检索 / 翻榜 / 读主页） | 读到的条目排序输出 |
| F0 无效喂料 | `false` | **序 5** | `false` | 无 | **0 条** + blockers |

`baseline_required_for_sufficiency = true` 时唯一变化：F1 额外要求「至少一条存活条目
所属账号基线齐备」，否则该喂料降为 F2。**分支编号不变。**

`branch = 1` 时 run-plan 输出的 `d2_allowed = false`，SKILL.md 正文规定模型见到 `false`
即禁止调用任何网页工具。`rank_render.build_final` 在 `branch` 为 3 或 5 时**强制输出 0 条**，
即使上游传进来条目也不渲染——否则「无通路」会被渲染成看起来有结果的清单。

## 序 1 的判定边界

「只有一个数字 + 无榜单标记」→ 有指标有数 → 可判定 → F1 充分 → 序 1 → **不上网**。
这条边界被显式写死并进 selftest（C2 用例）。

| 喂料形态 | feed_state | 结果 |
|---|---|---|
| 标题 + 地址 + 一个可见数字，无榜标记 | F1 | 序 1，不联网 |
| 标题 + 地址 + 榜单字样，无数字 | F1 | 序 1，不联网 |
| 标题 + 地址，无数字无榜标记 | F2 | 序 2 或 3 |
| 有标题无地址，或有地址无标题 | F0 | 序 4 或 5 |
| 全部条目都被内容过滤标记丢弃 | F0 | 序 4 或 5 |

## 0 条时的 blockers 文案

由 `normalize_feed.build_blockers` 从字段级统计渲染，**模型不得自行撰写措辞**。
三个字段：

| 字段 | 内容 |
|---|---|
| `missing_fields` | 缺哪些字段的条目各多少条（由 `dropped[]` 与存活条目统计得出） |
| `accepted_fields` | 喂料形式清单：链接原文 / 截图文字 / 粘贴列表内容 / 账号主页内容 |
| `need` | 需要用户喂什么 |

禁止出现「你可以自己去搜 XX 榜」类方法指导（N5、E6）。`rank_render.render_blockers`
只把这三段渲染成固定版式，不加任何分析或建议。

## 计数口径

**run-plan.json** 的 `counts` 四个数：

| 键 | 含义 |
|---|---|
| `input` | `items` 数组长度 |
| `alive` | 通过入场券的条目数（存活） |
| `judgeable` | 存活且可判定的条目数 |
| `dropped` | 被丢弃的条目数（含入场券不过关与内容过滤） |

恒等式：`input == alive + dropped`。
