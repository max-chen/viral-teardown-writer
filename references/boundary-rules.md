# 边界规则：N1–N15 落地细则与常见坑

本文件是「不做什么」的查阅型细则。每条给出**可机器验证的落点**，不靠自觉。

## N1 不写文案

- 不生成标题、不改写标题、不润色、不续写、不编口播稿
- 落点：`rank_render.truncate_caption` 只做截断与排版折叠（连续空白折叠为单个空格），
  不删字、不加字、不改字面

易误判：把原文里明显不通顺的句子「顺手改通顺」。这仍是改写。照抄，哪怕有错别字。

## N2 不改写

- 页面文案只能原文摘录；禁止改写、缩写、翻译、纠错
- 落点：去重时**只择一保留，严禁字段拼接**。caption 拼接即改写

易误判：同一条内容跨榜出现时，把两条的文案合并成一段「更完整的」。错，两条择一。

## N3 不给选题建议

- 不推荐「你可以拍什么」，不输出选题清单
- 落点：输出末尾禁止「建议 / 下一步」小节（`rank_render.post_assertions`）

易误判：在 0 条时写「建议你先去搜 XX 榜」。这既是建议也是方法指导，两条都踩。

## N4 不总结规律

- 不输出「爆款共性」「可复用套路」「内容方法论」
- 落点：同上，末尾禁止「总结 / 规律 / 方法论 / 小结」小节

易误判：给输出加一句「以上爆款集中在近期高频发布的家居题材」。这是归因，越界。

## N5 不教拍摄方法

- 不给镜头 / 运镜 / 灯光 / 剪辑 / 发布时段建议
- 落点：0 条说明只说「缺什么字段」与「需要喂什么内容形式」，不说「去哪里找」

易误判：把 `accepted_fields` 写成「可以去小红书热榜页复制」。改成中性的
「页面截图里的文字」，只描述**内容形态**，不描述**获取路径**。

## N6 不做数据估算

- 不预测播放量、不推算点赞、不换算不存在的指标、不用「大约 / 预计 / 左右」修饰数字
- 落点：`normalize_metric` 三态制。只有 `EXACT` 进算术；
  `VERBATIM`（带修饰词）照抄但不进算术；`UNPARSABLE` 标「未获取」计 0

易误判一：拿 `约50万` 当精确值算 3 倍比值。那是变相估算。VERBATIM 项不参与阈值判定。
易误判二：页面只写点赞没写播放，就把点赞当播放填进「凭什么算爆款」。那是换算不存在的指标。

## N7 不做竞品分析 / 账号诊断

- 不解释账号为什么火，不做同行横向对比
- 落点：输出只有五个字段，没有「分析」「对比」位

易误判：在证据里写「该账号平时播放仅 1.8 万，属于低频爆款」。前半句有页面依据，
后半句「属于低频爆款」是判断，去掉。

## N8 不凑数

- 不足 10 条就输出实际条数，禁止用「未获取」条目或低质量条目补满
- 落点：`rank_render` 截断到 10 但**不补位**；0 条就是 0 条

易误判：只有 3 条时把 C 档（无任何证据）的条目也塞进输出凑够 10。
C 档本身可判为「未获取」，但它进不了前 10（排序键 tier_rank 把它排在最后），
被截断掉是正确的。

## N9 不猜链接

- 地址必须是页面上真实存在的原链接，禁止按 ID 规则拼装、禁止改写 URL 参数
- 落点：地址准入判据含「溯源核验通过」+「query 不含凭据型参数名」；
  短链**照抄**，禁止展开跳转、禁止猜真实域名、禁止改写成自生成 URL

易误判一：看到 `https://url.cn/5abXyZ` 就想「这大概是快手」，写成快手链接。
平台字段填「未获取」，地址原样照抄。
易误判二：给短链补 `?share_token=xxx` 让它「更完整」。禁止，那是我们生成的。

## N10 不越界替用户决策

- 不在清单外附加任何评价、推荐语或行动建议
- 落点：五字段块之外只有空行与下一个块首

易误判：末尾加「建议优先参考第 1、3 条」。越界。

## N11 不把「未获取」换成别的写法

- 字面量固定为「未获取」（数字）与「无文案」（文案）
- 禁止 `暂无` / **N/A** / `NA` / `-` / `--` / `null` / `None` / `0` / `未知` / `无数据`
- 落点：`rank_render.post_assertions` 逐行扫描五字段值，命中即 exit 2

## N12 无页面读取能力时不出条目

- 既无喂料又无网页读取工具 → 输出 0 条，宁可空手
- 落点：`branch` 为 3 或 5 时 `rank_render` 强制 0 条（即使上游传进来条目）

## N13 喂料够用时不上网

- 喂料足以判定时必须完全离线出结果
- 落点：**run-plan.json** 的 `d2_allowed = false`；`scripts/` 零网络 import
  （`../scripts/selftest.py` 用 AST 断言，可机器验证）；`branch = 1` 即禁止调用网页工具

## N14 不用喂料内容当许可证

- 用户口头提供的数字若不在喂料页面内容中，仍按「未获取」处理
- 落点：每个叶子值的 `raw` 必须通过子串核验，核不过即降级。
  这是「只认页面上写着的」在喂料模式下的机器落点

易误判：用户说「这条应该有 50 万播放」，模型就把 `50万` 写进 **feed.json**。
核验会拦下——原文里没有这个串，该项降级为「未获取」。

## N15 不因追问而破例

- 用户追问「那你大概判断一下」「你就估一个吧」也不破例，重申边界后仍不破例
- 落点：渲染层自造修饰词黑名单（`大约 / 预计 / 左右 / 可能超过` 等）命中即 exit 2。
  注意扫描前会先剔除全部 `raw` 原文，所以页面原文里的 `约` 不会被误判

## 8 类不触发负例

以下场景**不触发**本技能，description 与正文的「不触发」条款必须能覆盖：

| 负例 | 归哪条禁区 |
|---|---|
| 给我 5 个选题 | N3 选题建议 |
| 帮我写这条视频的口播文案 / 标题 | N1 写文案 |
| 分析一下这个账号为什么火 | N7 账号诊断 |
| 总结这批爆款的共同规律 | N4 规律总结 |
| 这几个爆款有什么共同点 | N4 规律总结 |
| 教我怎么拍 | N5 拍摄方法 |
| 预估这条能有 50 万播放吗 | N6 数据估算 |
| 竞品账号对比 / 同行数据分析 | N7 竞品分析 |

## 常见坑速查

| 坑 | 正确做法 | 机器落点 |
|---|---|---|
| 推荐流当 A 档 | 只有榜单位字样或带名次排名才是 A | `assign_tier` |
| 中位数偶数取值 | 取中间两数均值，不是 `sorted()[n//2]` | `median_exact` |
| 中位数展示用 round | 银行家舍入会让「可复算」失效，用 divmod 拼精确文本 | `median_exact` |
| 3 倍边界抖动 | 含等号，纯整数 `target*den >= 3*num` | `ratio_passed` |
| 中位数为 0 | 一律判不通过，不写相对结论 | `ratio_passed` |
| 同链接重复占名额 | 按 URL 逐字节去重，保留证据最强的一份 | **rank_render.dedup** |
| 短链被展开 | 照抄短链原文，禁止展开与改写 | `resolve_platform_field` |
| 喂料当许可证 | 每个 `raw` 过子串核验 | `verify_raw` |
| 修饰词被改写 | `约50万` 照抄，不改 `500000`，不剔除后写成 `50万` | `append_sum_note` |
| 样本不足虚报 | 不足 10 条按实际条数，证据写实际样本数 | `compute_baseline` |
| 指标退化不可见 | 退化时在证据里写明「判定所用指标：点赞」 | `append_sum_note` |
| 文案截断补全 | 只截断并标注，不因截断改写或补全 | `truncate_caption` |
| 探测失败重试 | 探测一次即定论，`attempts` 必须等于 1 | `probe_d2.validate` |
| 无通路仍出条目 | `branch` 为 3 或 5 时强制 0 条 | `build_final` |
