# 写稿段硬红线规则表

`../scripts/draft_check.py` 的确定性规则唯一事实源。改阈值改这里 + 改脚本常量，两处必须同步。

## 一、为什么分「机器判定」与「不判定」

本表只列**机器能判、判了不会错**的规则。凡是需要理解语义才能判的，一律不写进脚本——

**理由**：误报只会让人绕开工具。一条会错杀好稿的检查，比没有检查更糟。

## 二、机器判定的规则（脚本拦截）

| 规则号 | 拦什么 | 判据 | 改法 |
|---|---|---|---|
| `W-BLOCK-COUNT` | 块数不对 | 必须恰好 4 块 | — |
| `W-BLOCK-ORDER` | 块顺序错| 必须 标题→正文→内核→改口 | — |
| `W-BLOCK-SEQ` | 块序号错 | 第 N 块必须标 N | — |
| `W-BANNED-WORD` | 空心词 | 标题/正文含「高级感、氛围感、质感、绝了、震惊、神器、必看」 | 改 `BANNED_WORDS` |
| `W-OPENER` | 套话开头 | 正文**第一句**以「大家好 / 因此 / 综上所述」开头 | 改 `BANNED_OPENERS` |
| `W-CORE-ONELINE` | 内核超句 | 「内核」块非单行 | — |
| `W-REV-COUNT` | 改口少/多 | 必须恰好 3 行 | — |
| `W-REV-FORMAT` | 改口格式错 | 每行须匹配 `<原句> → <改后>`（容忍 `->` `➜`） | 改 `REVISION_LINE_RE` |
| `W-MATERIAL` | 空素材却编经历 | `--material` 为空且标题/正文含「我测过/我试过/我用过/我做过/我经历/我遇到/我发现/我当时/我买过/我吃过/我拍过」 | 改 `FIRST_PERSON_CLAIM_RE` |
| `W-PLAGIARISM` | 整句搬运 | 正文与原文（均压掉空白后）最长公共子串 ≥ `MAX_SHARED_SPAN` = 12 字 | 改 `MAX_SHARED_SPAN` |

## 三、故意不判定的部分（靠模型语义纪律）

| 不判定项 | 为什么不拦 |
|---|---|
| 「内核」是否真的抓准了爆款为什么能停住人 | 需要理解内容，误报率高 |
| 平台口气是否到位（抖音/小红书/公众号） | 需要主观判断，无可靠正则 |
| 一篇是否只讲一件事 | 纯语义 |
| 读出声是否顺 | 纯语义 |
| **素材非空时的编造** | 素材写了「我测过」是真经历，稿里写是如实转述；脚本分不出「素材里的真」与「编出来的真」。**只拦素材为空这一种可判定情形** |

## 四、「禁止换词」的落地裁决

用户原话两条打架：

> 只留下它为什么能停住人的内核…… **禁止换词**、禁止复述原句

**内核靠具体措辞承载**，换光词内核就空了；反过来照抄原句又违反「禁止复述原句」。

**裁决**：禁的是「整句搬运」，不是「不许用同一个词」。

- 落地为量化红线：正文与原文最长公共片段 ≥ 12 字即判洗稿
- 「爆款」「爆款」这类词若构成 12 字连续片段，与照搬原句无法区分，故一并拦
- 阈值可调，改 `MAX_SHARED_SPAN` 一处即可

**为什么不用逐词比对**：「禁止换词」字面不可判定——连「爆款」两个字都不许写吗？无法执行。

## 五、两个归一化函数，别混用

| 函数 | 用途 | 压换行吗 | 为什么 |
|---|---|---|---|
| `_norm` | 结构解析 | **保留** | 块首解析依赖行边界 |
| `_squeeze` | 洗稿检测 | **压掉** | 原稿换行参与比对会白送几十字；段间换行会把无关内容连成公共片段 |

**混用后果（已实际发生）**：用 `_squeeze` 解析块 → 整篇并成一行 → 合规稿被误判成「必须 4 块，实际 0 块」。改这块前先跑 `../scripts/selftest.py` 的 N 组用例。

## 六、禁用词只扫标题与正文

**「内核」「改口」两块不扫禁用词。** 理由：

- 改口块的作用就是写出你改掉的原句——原句里出现「神器级」是必要的
- 内核是对内核的概括，出现空心词说明概括没做到，但由语义纪律约束更合适

误杀比漏检更危险：一条会错杀好稿的检查会让人绕开工具。

## 七、退出码

| 码 | 含义 |
|---|---|
| 0 | 通过 |
| 2 | 违反硬红线（附规则号、块名、行号、修法），或文件不存在 |

不通过时模型应改稿重跑，最多 3 轮；仍不过则把违规项原样告知用户，**不许放宽检查让它过**。
