# viral-teardown-writer

两段式爆款流水线：**先找真爆款，再照它的内核写稿**。

中间那道缝是「爆款原文」字段——没有真实原文，写稿段不触发。这样「不许凭感觉编」不是一句叮嘱，而是技能的结构约束。

```
一 · 找爆款  →  最多 10 条，每条五字段，热度降序
                  ↓ 挑一条，当参考原文喂给第二段
二 · 写稿    →  只输出四块：标题 / 正文 / 内核 / 改口
```

## 为什么叫 teardown

teardown = 拆解爆款，writer = 写稿。

**「抄」= 拆解并复刻它为什么能停住人的内核，不是复制句子。** 脚本按住这一条：正文与参考原文最长公共片段 ≥ 12 字就判搬运（阈值在 `draft_check.py` 的 `MAX_SHARED_SPAN`，改一处即可）。

## 安装

```bash
unzip viral-teardown-writer.zip -d ~/.workbuddy/skills/
# 或直接把本仓库 clone 成 ~/.workbuddy/skills/viral-teardown-writer/
```

Python 3.8+，**零第三方依赖**，只用标准库。若安装过旧版 `viral-to-post`，请删掉旧目录，避免两套并存导致唤起不确定。

装完说一句「抄爆款」验证唤起——它应按「缺平台 / 赛道」追问一次；再说「给我 5 个选题」，应不触发。

## 怎么用

**找爆款**（给平台 + 赛道 + 时间，或直接喂页面内容）

```
找一下小红书近 7 天家居赛道的爆款，只要链接和数字
```

**写稿**（带上一段挑出来的原文）

```
照这条爆款写一篇，平台抖音，选题是「40 岁转行 AI」，
素材：我做了 5 年自媒体，上周发的第一条口播只有 200 播放。
参考原文：<把第一段输出的文案贴进来>
```

## 第一段：只认看得见的数字

每条固定五字段，最多 10 条，按热度降序：

```text
第 1 条
标题：<页面原文标题>
地址：<页面上的原链接>
平台：<平台>
凭什么算爆款：<榜单依据或页面原始数字>
文案：<原文摘录，超 300 字截断并标注>
```

四条铁律：

- 数字必须在页面上写着，没写就标「未获取」，**禁止估算、禁止编**
- `约50万` 照抄，`500000` 不行——不许改写
- 短链（xhslink.com / b23.tv）照收照抄，不展开、不猜真实域名
- 输出末尾不附任何总结、规律、建议

喂料够用时不上网；既无可用喂料、环境又无网页读取能力时，**输出 0 条并说明缺什么**——0 条是正确行为，退出码仍是 0。

## 第二段：四块，一条不多

写稿只输出：标题 / 正文 / 内核 / 改口。改口必须恰好 3 处「原句 → 改后」。

`scripts/draft_check.py` 机器卡死的红线：

| 规则 | 拦什么 |
|---|---|
| W-BLOCK-COUNT / ORDER / SEQ | 恰好四块、顺序固定、无越界第五块 |
| W-BANNED-WORD | 高级感、氛围感、质感、绝了、震惊、神器、必看（只扫标题与正文） |
| W-OPENER | 正文第一句不得以「大家好 / 因此 / 综上所述」开头 |
| W-CORE-ONELINE | 内核必须一句话 |
| W-REV-COUNT / FORMAT | 改口恰好 3 处，每处「原句 → 改后」 |
| W-MATERIAL | 素材为空却出现「我测过 / 我当时…」 |
| W-PLAGIARISM | 与参考原文最长公共片段 ≥ 12 字 |

```bash
python3 scripts/draft_check.py --draft draft.md --material material.txt --source source.txt
# exit 0 = 通过，2 = 违规（报规则号、块名、行号、修法）
```

### 脚本故意不管的部分

误报比漏检更危险——一条会错杀好稿的检查会让人绕开工具。以下靠你自己看：

- 内核是否真的抓准了它为什么能停住人
- 平台口气是否到位（抖音像当面说话 / 小红书先给结论 / 公众号把事讲完，不混用）
- 一篇是否只讲一件事、读出声是否顺
- 素材非空时的编造：脚本分不出「素材里的真」和「编出来的真」，只拦「素材为空」这一种可判定情形

## 自检

```bash
python3 scripts/selftest.py    # 354 / 354，exit 0
```

管线是 `probe_d2 → normalize_feed → judge_evidence → rank_render`：模型负责语义解析（平台 / 赛道 / 时间、网页读取），脚本负责取证与判定（溯源核验、单位归一、中位数 3 倍阈值、四级排序、渲染）。分工边界写在 `references/boundary-rules.md`。

## 残留风险

1. **链接是否真能打开，离线验不了**——第一次用请手动点开一条抽检。
2. 写稿段内容质量无机器保障，这是设计取舍，不是缺陷，但要知道它存在。
3. 短链与其展开目标同内容时按 raw 键算两条，允许同内容占 2 席（不跳转就认不出同源，按 host 猜违反禁令）。
